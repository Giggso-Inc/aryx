POST /admin/docs/confirm

Entity resolution funnel · graph projection · first time aryx_entity is written

Outer loop — ingest_confirmed() runs ALL approved_types first (one at a time), THEN all approved_files

Document entity types path

For each approved_type, one after another: filters the mention list by type, wraps in RecordsConnector(recs, label=otype), runs the full pipeline with match_keys=["name"], relate=True. skip_graph is never passed → defaults False, so every type gets its own immediate graph rebuild.

Tabular files path

Detects FK links twice — once across this batch's files (_detect_fk_links), once against types already in the workspace from earlier confirms (_detect_fk_links_workspace). Non-last files run in parallel (ARYX_INGEST_WORKERS, default 3) with skip_graph=True, relate=False. The last file runs serially afterward with fk_links=auto_fk, skip_graph=False, and relate only if ARYX_INGEST_RELATE=true (default off).

Multi-sheet Excel & multi-entity XML — split into derived files BEFORE /confirm
/read already expanded any uploaded .xlsx workbook into one CSV per visible worksheet (_xlsx_to_csvs(), named "{workbook_stem}__{sheet_slug}.csv") and any multi-entity .xml into one CSV per element type (_xml_to_csvs()). approved_files must name these derived filenames — exactly as shown by /summary — not the original workbook/XML name. Each derived file then flows through the tabular path independently.

Orchestration — doc_discovery.py :: ingest_confirmed()
Per-file setup, BEFORE any run_pipeline() call
Runs once for the whole /confirm request, before the tabular files loop below:
1. FK detection, pass A (in-batch): _detect_fk_links(valid_plans) — 3 rules: naming pattern ({Type}_id/_name), shared-suffix code columns, XML element-type FK.
2. FK detection, pass B (workspace-wide, new): _detect_fk_links_workspace(last_plan, known_types) — matches the last file's columns against ontology types already registered from earlier confirms, so single-file jobs still find FK links.
3. Source provenance (new): _persist_xml_sources(valid_plans) — for XML/XLSX-derived plans only, saves the original workbook/XML bytes + list of derived CSV assets to the source catalog.
Non-last files run in parallel, last file runs alone afterward
ThreadPoolExecutor(max_workers=ARYX_INGEST_WORKERS) (default 3) runs every file except the last concurrently, each with skip_graph=True, relate=False. A failure in a non-last file is logged and skipped — the rest continue. The last file always waits for all others to finish, then runs alone with fk_links=auto_fk, skip_graph=False, relate=is_last and ARYX_INGEST_RELATE (default off). This ordering exists because (a) FK links need every other file's entities to already exist, and (b) FalkorDB projection clears + rebuilds the whole graph — two of those running at once would race.
IN: approved_files, tabular plans OUT: auto_fk[] specs, per-file run order DB: source catalog (DatasourceStore) — XML/XLSX only

2.0 — Exact-ID fast path (new, deterministic, no API) — ARYX_ER_EXACT_ID_MATCH (default true)
When every match key is literally id/uuid/guid/key, blocking/embedding/scoring are skipped entirely — records merge only on exact string equality of the normalised match text.
Why: fuzzy similarity is wrong for opaque ids — sequential ids like 18722401146 vs 18722401147 score 0.90+ and, because merging is transitive, can collapse a whole id range into one entity. Two blank match texts never merge either (fuzzy scoring would otherwise treat "" == "" as a perfect match).
2a — Blocking (when not in exact-ID mode; deterministic, no API)
block(records) — groups candidates to avoid O(n²) comparison:
  • 4-char prefix of match text
  • Token-set canonical form (sorted lowercase tokens)
  • Soundex of first token
Records only compete within the same block.
2b — Embedding per block (API A)
_block_embeddings(group, broker) — embeds match texts for cosine similarity.
Capped at _embed_cap = √(2 × max_pairs_per_block) records per block.
Skipped entirely when ARYX_ER_AUTO_MERGE ≥ 1.0 AND ARYX_ER_ADJUDICATE ≥ 1.0.
Silent fallback to string-only if embed fails for a batch.
2c — Scoring per pair (no API)
score_pair(left.text, right.text, vec_left, vec_right)
Combined float [0.0, 1.0] = weighted(token-set ratio + Jaro-Winkler + cosine similarity)

Clustering — UnionFind + golden record (survivorship policy, not just confidence)
After all pairs are routed (or after 2.0's exact-match grouping), UnionFind.groups() produces clusters.

For each cluster → _materialize(member_ids, ...):
  • Per-workspace survivorship policy (default strategy "most_complete") decides, per attribute, which contributing record's value survives — usually not simply the member with the highest overall match confidence
  • Conflicting values logged → aryx_attribute_conflict (strategy name recorded, e.g. "most_complete")
  • cluster_confidence(edges, n_members) → separate entity-level confidence score (how sure the resolver is these are the same entity)
  • Fallback only: golden_record_weighted() (highest-confidence wins) if no policy object exists — not normally reached from /confirm

Stage 3 / 5 — Relate (relate=True — approved_types always; tabular files only if last AND ARYX_INGEST_RELATE=true, default off)
LLM Relationship Inference — pipeline/enrich.py:_relate()
Not a flat loop over every entity pair. Samples entities per type so every type is represented, builds cross-type pairs first (round-robined across type combos), then fills remaining budget with same-type pairs. Capped at effective_pairs = min(ARYX_MAX_RELATE_PAIRS, cross_type_combos) — ARYX_MAX_RELATE_PAIRS defaults to 10, a true hard cap (the schema-wide pass below covers full-population FK discovery). A "coverage guarantee" forces one extra pair for any type the round-robin left completely unrepresented.
Runs concurrently (ARYX_RELATE_WORKERS, default 4); abandons still-pending calls after ARYX_RELATE_PAIR_TIMEOUT (default 30s) of no progress — a stuck call must not hang the ingest.

3b — Schema-wide FK inference (new) — pipeline/enrich.py:_infer_schema_fk_links() — same relate=True gate, runs right after 3
Stage 3 only samples a handful of entities per type, so it can miss FK-shaped columns that don't follow naming conventions. This step sends column names only (one sample entity per type, ≤8 types per LLM call, batched with an "anchor" type included in every batch) and asks which attributes across types look like foreign keys. Whatever it proposes is applied via link_by_attribute() — same mechanism as Stage 4 — but creates edges for every matching entity in the workspace, not just the sampled few.

Stage 4 / 5 — FK Link (last approved file only, deterministic)
Cross-file Join — pipeline/fk_edges.py:link_by_attribute()
Uses the auto_fk specs from two detection passes run once before the file loop — _detect_fk_links(valid_plans) (in-batch: naming pattern + shared-suffix code columns + XML element-type) and _detect_fk_links_workspace(last_plan, known_types) (new — matches against ontology types already registered from earlier confirms, so single-file jobs still find links):

Pattern: if orders.csv has column customer_id → matched against customers.csv by {TypeB}_id naming convention. 
link_by_attribute(
    estore,
    source_type="Order",         # entity carrying the FK
    source_attr="customer_id",   # FK column name
    target_type="Customer",      # entity being referenced
    target_attr="id",            # PK or match key in target
    name="CUSTOMER_HAS_ORDER",   # edge label
)
→ exact match: order.attributes["customer_id"] == customer.attributes["id"]
→ INSERT aryx_relationship for each matched pair
No LLM call here
FK linking is deterministic pattern matching on column names and attribute values. No embedding, no adjudication.
4b — Relate-isolated safety net (new) — pipeline/enrich.py:_relate_isolated() — ALWAYS runs, not gated by relate
Runs for every run_pipeline() call, right after FK Link, right before Project — even when relate=False. Finds every entity in the workspace with zero relationship edges (store.list_isolated_entities(), one query), groups them by type, and makes one LLM call per isolated type (not per entity) against a sampled anchor entity of some other type. If related, creates one edge per isolated entity of that type → the anchor. Keeps the LLM call count bounded at ~"number of isolated types" even for a 20-type, thousand-row XML upload — this is what guarantees no orphan nodes after ingest, independent of whether relate was ever enabled.
IN: fk_links[] specs, aryx_entity attributes, isolated entities DB: aryx_relationship INSERT 4b only: API C3 — LLM frontier tier, one call per isolated type

Documentation Corrections Log — audited against source 2026-07-16
14 drift points found and fixed vs. current code
1. Multi-sheet .xlsx support (_xlsx_to_csvs()) was completely undocumented — added.
2. _detect_fk_links_workspace() (Pass B, workspace-wide FK detection) was missing — added.
3. _persist_xml_sources() source-catalog provenance step was missing — added.
4. Tabular-file relate=True was claimed unconditional; actual code gates it on is_last AND ARYX_INGEST_RELATE (default off) — corrected.
5. skip_graph (non-last files defer graph writes) was undocumented — added, with the FalkorDB race-condition rationale.
6. Parallel non-last-file execution (ARYX_INGEST_WORKERS) and partial-failure tolerance were undocumented — added.
7. approved_types loop passes no skip_graph/relate gating → every type gets an immediate full graph rebuild — called out explicitly.
8. Two pipeline sub-stages were entirely missing: schema-wide FK inference (3b) and the relate-isolated safety net (4b) — added in full.
9. ARYX_MAX_RELATE_PAIRS was documented as defaulting to 100; actual default is 10 — corrected, plus added the type-aware sampling/coverage-guarantee logic.
10. The exact-ID fast path (ARYX_ER_EXACT_ID_MATCH, default true) was undocumented — added as step 2.0.
11. Golden-record merge described only the confidence-weighted fallback; the primary path uses a per-workspace survivorship policy (default "most_complete") — corrected.
12. Post-ingest zero-loss validation (ingest_validation.py) was entirely undocumented — added as its own timeline step.
13. Resume/checkpoint support (resume_run_id, StageRunner/StageTracker) was undocumented — added as a resilience note.
14. Minor: RecordsConnector(recs) corrected to RecordsConnector(recs, label=otype).
