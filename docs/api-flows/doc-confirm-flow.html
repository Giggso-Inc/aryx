Entity resolution funnel · graph projection · first time aryx_entity is written

Outer loop — ingest_confirmed() iterates over approved types then files

Document entity types path

For each approved_type: filters the mention list by type, wraps in RecordsConnector, runs full pipeline. match_keys=["name"].

Tabular files path

Detects FK links across all approved files once. For each file: CsvConnector or JsonConnector. Last file gets fk_links — by then all prior entities exist.

Stage 2 / 5 — Resolve
Entity Resolution Funnel — resolution/run.py:resolve()
records = store.landed_records(run_id, key_attrs)
SELECT aryx_landed WHERE run_id=? AND workspace_id=?

For each row, build match text:
text = " ".join(str(payload.get(a, "")) for a in key_attrs)
e.g. match_keys=["name"] → text = "INV-2024-001"
2a — Blocking (deterministic, no API)
block(records) — groups candidates to avoid O(n²) comparison:
  • 4-char prefix of match text
  • Token-set canonical form (sorted lowercase tokens)
  • Soundex of first token
Records only compete within the same block.
2b — Embedding per block (API A)
_block_embeddings(group, broker) — embeds match texts for cosine similarity.
Capped at _embed_cap = √(2 × max_pairs_per_block) records per block.
Skipped entirely when ARYX_ER_AUTO_MERGE ≥ 1.0 AND ARYX_ER_ADJUDICATE ≥ 1.0.
Silent fallback to string-only if embed fails for a batch.
2c — Scoring per pair (no API)
score_pair(left.text, right.text, vec_left, vec_right)
Combined float [0.0, 1.0] = weighted(token-set ratio + Jaro-Winkler + cosine similarity)

Stage 4 / 5 — FK Link (last approved file only, deterministic)
Cross-file Join — pipeline/fk_edges.py:link_by_attribute()
Uses the auto_fk specs from _detect_fk_links() — run once across all approved files before the loop:

Pattern: if orders.csv has column customer_id → matched against customers.csv by {TypeB}_id naming convention. 
link_by_attribute(
    estore,
    source_type="Order",         # entity carrying the FK
    source_attr="customer_id",   # FK column name
    target_type="Customer",      # entity being referenced
    target_attr="id",            # PK or match key in target
    name="CUSTOMER_HAS_ORDER",   # edge label
)
→ exact match: order.attributes["customer_id"] == customer.attributes["id"]
→ INSERT aryx_relationship for each matched pair
No LLM call here
FK linking is deterministic pattern matching on column names and attribute values. No embedding, no adjudication.
IN: fk_links[] specs, aryx_entity attributes DB: aryx_relationship INSERT
