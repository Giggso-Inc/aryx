Per-Document Timeout & Worker Concurrency — doc_router.py
ARYX_PER_DOC_TIMEOUT (default 7200s / 2h) — hard wall-clock budget per document. A hang in parse/OCR/embed/extract abandons that one document (logged as error); the rest of the batch continues.
ARYX_DOC_WORKERS (default 1, sequential) — how many documents run at once. Raise only for cloud LLM backends that can truly handle concurrent requests; a local CPU Ollama gains nothing from parallelism.

step 2/8
Chunk Pages — pipeline/clean_text.py:chunk_pages()
Sub-step 1 — Normalize (_normalize(text)):
  • unicodedata.normalize("NFC", text) — canonical unicode form
  • re.sub(r"-\n(\S)", r"\1", text) — rejoin hyphenated line-breaks
  • re.sub(r"\n{3,}", "\n\n", text) — collapse 3+ blank lines to 2

Sub-step 2 — Sliding window split:
  • chunk_size = ARYX_CHUNK_SIZE (default 1000 chars)
  • overlap = ARYX_CHUNK_OVERLAP (default 100 chars)
  • start=0, end=start+chunk_size, next start=end-overlap 
page text:  [────────────────────────────────────────────────]
chunk 0:    [──────────────────────────]
chunk 1:             [──────────────────────────]
chunk 2:                      [──────────────────────────]
            ←──── 1000 chars ────→
                     ←── 100 ──→ (overlap)
Each DocumentChunk: doc_id · chunk_index · page_slide · text · char_start · char_end · source
No text leaves the machine at this step. PII screening runs before any external call.

Verbatim-Span Gate (deterministic — no API cost)
def _verbatim_ok(name, span): return name.lower() in span.lower()

Any mention where name is absent from span is silently dropped.
Prevents hallucinated entity names from reaching resolution or the graph.

✓ PASS: name="INV-2024-001" span="Invoice INV-2024-001 dated Jan 15"
✗ DROP: name="Q1 Invoice" span="Invoice INV-2024-001 dated Jan 15"

Chunk failures (network/LLM error): chunk skipped, rest continue — logged at WARNING.
Gate rejections: logged at DEBUG.

Tabular Path — Step T1: Normalize (JSON / CSV / XML / XLSX files)
Runs independently of the 8-step document pipeline. No OCR, chunking, PII screening, or embeddings here — the data is already structured. Goal: split each upload into one clean CSV per record type.
.csv → _consolidate_csv_names()
Passed through as-is, except multi-part name columns (COMPANY_NAME, COMPANY_NAME_2 … COMPANY_NAME_5) get merged into one name column.

Why: some government/defense exports split a long org name across columns due to a legacy fixed-width limit. No-op when there's nothing to merge.
.xml → _xml_to_csvs()
Entity = element with ≥2 distinct child element types, or ≥1 XML attribute if it's a leaf. Multilingual fields collapse to one value (English preferred). {parent_tag}_id FK column injected on every child row automatically.

Caps: ARYX_XML_MAX_ENTITY_TYPES (default 20, named types preferred) · ARYX_XML_MAX_ROWS_PER_TYPE (default 500) — guards against ERP/CPQ exports with dozens of element types and huge row counts.
.xlsx → _xlsx_to_csvs() — multi-sheet Excel ingestion
✦ New: earlier revisions of this endpoint had no .xlsx support at all — DATA_EXTS did not include it.
Every visible worksheet becomes its own CSV, mirroring _xml_to_csvs()'s shape so the rest of the pipeline needs no separate spreadsheet code path.

Skipped (never ingested as garbage datasets): hidden/"very hidden" sheets · sheets with no header row · sheets with a header but zero data rows (e.g. a blank "Template" tab).

Naming: "{workbook_stem}__{sheet_slug}.csv" — e.g. orders.xlsx with sheets "Customers" / "Order Items!" → orders__Customers.csv, orders__Order_Items.csv. The shared {stem}__ prefix lets a later query recover every sheet from one workbook upload.

Reads via openpyxl in read-only streaming mode (no full workbook in memory).
IN: .xlsx bytes OUT: list[(csv_bytes, "{stem}__{sheet}.csv")]

Audit Note — Drift Fixed in This Revision
•.xlsx was entirely missing. DATA_EXTS now includes .xlsx; added the full _xlsx_to_csvs() multi-sheet ingestion path (one CSV per visible worksheet, hidden/empty sheets skipped).
•CSV name consolidation was undocumented. Added _consolidate_csv_names() — merges split COMPANY_NAME_2-style columns into name.
•Wrong XML cap. Corrected "top-3 most-frequent element type" → actual caps are ARYX_XML_MAX_ENTITY_TYPES (default 20) and ARYX_XML_MAX_ROWS_PER_TYPE (default 500).
•JobStore.create() signature was incomplete. Corrected to the real 4-argument call: create(job_id, system, dataset, workspace_id).
•No per-document timeout / concurrency. Added ARYX_PER_DOC_TIMEOUT (default 2h) and ARYX_DOC_WORKERS (default 1) as a new pipeline-level card.
•No connection-pooling note. Added a line noting ChunkStore/JobStore now borrow from a shared pool; .close() is a no-op.
•Everything else — the 8-step document pipeline, API Calls A-C, the verbatim-span gate, and the /confirm entity-creation boundary — matched current code and was left as-is (only reworded for clarity).
