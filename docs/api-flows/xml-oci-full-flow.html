XML File · OCI Mode — /read → /confirm Full Flow

XML is structured data (DATA_EXTS), not a document — it bypasses the document pipeline entirely. OCI Document Understanding is never called. Every LLM + embed call routes to OCI GenAI. Project stage writes to Oracle Graph, not FalkorDB.

File Router — _read_job()
XML → DATA_EXTS (tabular path)
⚠ .xml is in DATA_EXTS, not DOC_EXTS — the entire 8-step document pipeline is skipped. No OCI Document Understanding. No chunking. No PII screen. No embedding. No NER. No aryx_document / aryx_chunk / aryx_chunk_embedding writes.
DOC_EXTS (.pdf .docx .pptx .ppt .rtf .html .htm images) → document pipeline → not this path
DATA_EXTS (.json .csv .xml) → tabular path → this path ✓
IN: catalog.xml bytes OUT: tabular=[(bytes, "catalog.xml")]
Local XML Parser — doc_discovery.py:_xml_to_csvs()
XML → N CSVs (one per top-3 element type)
Parses with defusedxml.ElementTree (safe against XML bombs).
Counts all child element tags across the whole tree, takes the top-3 tags appearing ≥2 times.
Example — catalog.xml input:
<catalog>
  <product id="P1" name="Widget A" price="9.99">
    <category id="C1" name="Widgets"/>
  </product>
  <product id="P2" name="Widget B" price="14.99">
    <category id="C1" name="Widgets"/>
  </product>
</catalog>
Output CSVs (catalog_product.csv + catalog_category.csv):
catalog_product.csv:
  _element_type, id,  name,     price,   catalog_id
  product,       P1,  Widget A, 9.99,    (root attr or None)
  product,       P2,  Widget B, 14.99,   ...

catalog_category.csv:
  _element_type, id,  name,    product_id   ← injected FK
  category,      C1,  Widgets, P1
  category,      C1,  Widgets, P2
Each child CSV gets a {parent_tag}_id column injected automatically. This is how _detect_fk_links() later finds the relationship between entity types — it looks for the {TypeB}_id naming pattern.
IN: catalog.xml bytes, stem="catalog" OUT: [(csv_bytes, "catalog_product.csv"), (csv_bytes, "catalog_category.csv")]
